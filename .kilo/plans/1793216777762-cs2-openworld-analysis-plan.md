# CS2 Open World - Архитектурный анализ и план развития

## Обзор проекта

CS2 Open World - модульный серверный плагин для Counter-Strike 2, построенный на базе Metamod:Source и hl2sdk-cs2. Проект ориентирован на создание многосерверного open-world с авторитетностью сервера, модульной архитектурой и персистентным хранением данных.

**Текущая версия:** 0.0.1  
**Платформа:** Windows/Linux (x64)  
**Язык:** C++20  
**Сборка:** CMake

## Архитектура

### Текущая реализация

#### Ядро (Core)
- **ModuleManager** - управление модулями с разрешением зависимостей, инициализацией/запуском/остановкой. Поддерживает топологическую сортировку, откат при ошибках.
- **EventBus** - локальная шина событий между модулями одного процесса. Типобезопасная с поддержкой отписки.
- **ServiceRegistry** - реестр сервисов для слабосвязанного взаимодействия модулей через интерфейсы с версионированием.
- **ClusterConfig** - парсинг и валидация `openworld.ini`. Поддержка серверов, зон, настроек PostgreSQL/Redis.
- **OpenWorldPlugin** - главный класс плагина, интеграция с Metamod, хуки CS2, управление жизненным циклом.

#### Адаптеры (Adapters)
- **PostgreSQLAdapter** - динамическая загрузка libpq, параметризованные запросы. Реализует: создание/загрузка персонажа, загрузка/сохранение настроек игрока, идемпотентные денежные транзакции. Встроенный локальный кеш настроек (512 записей, 4MB, TTL 30с).
- **ClientRedirector** - валидация endpoint'ов и отправка команды `connect` клиенту для межсерверного перехода.

#### Модули (Modules)
- **TransferManager** - state machine для межсерверных переходов (Requested → Validating → ... → Completed/Failed). Базовая реализация с идемпотентностью.
- **PlayerSettingsWorker** - фоновой загрузчик настроек игрока вне игрового потока.
- **Persistence** - содержит экспериментальные компоненты (CacheManager, RedisCache, PlayerWarmup) отключенные по умолчанию.

#### UI
- **Particle UI** - прототип меню на основе частиц. Модель меню с 6 слотами, виртуальный курсор, сессии по SteamID. Рендеринг/сущности не подключены.

### Зависимости
- **Metamod:Source** - фреймворк плагинов для Source 2
- **hl2sdk-cs2** - SDK движка CS2
- **libpq** - PostgreSQL клиент (runtime, динамическая загрузка)
- **khook** - hooking библиотека (в third_party)
- **protobuf** - для сериализации (генерируется CMake)

## Текущее состояние реализации

### Работает
- Загрузка плагина, хуки жизненного цикла
- Проверка Steam-аутентификации через `IVEngineServer2`
- Парсинг конфига кластера с валидацией
- Подключение к PostgreSQL при старте
- Локальный кеш настроек игрока (только для PlayerSettings)
- Фоновая загрузка настроек после полной аутентификации
- Команда чата `!go <server_id>` / `!transfer` для простого reconnect
- Валидация endpoints для редиректа
- Базовые unit-тесты для core компонентов

### В разработке/не реализовано
- Автоматический выбор персонажа при входе
- Сохранение состояния персонажа/позиции при выходе
- Полноценный межсерверный transfer с сохранением состояния
- Применение зон для маршрутизации
- NPC, диалоги, квесты, инвентарь, экономика (только базовые функции в БД)
- Рендеринг Particle UI
- Workshop интеграция
- Модули gameplay (NPC, Dialog, Quest, Inventory и др.) - только заглушки/структура

## Технические рекомендации

### Архитектурные принципы (из спецификации)
1. **Модульность** - четкие границы ответственности
2. **Расширяемость** - легко добавлять/отключать модули
3. **Авторитетность сервера** - клиент не может назначать себе ресурсы
4. **Независимость UI** - игровая логика не зависит от механизма отображения
5. **Независимость БД** - модули не пишут SQL напрямую, используют репозитории/адаптеры
6. **Безопасность жизненного цикла** - не хранить сырые указатели на сущности движка долго

### Best Practices
- Использовать ServiceRegistry для межмодульного взаимодействия
- Использовать EventBus для уведомлений
- Все критичные операции через PostgreSQL с проверками
- Идемпотентность для транзакций
- Валидация на сервере
- Логирование через PLUGIN_LOGTAG

### Известные ограничения
- Лимит сущностей CS2 (~32768) - не расширяем плагином
- Бесшовный переход между серверами не подтвержден
- Particle UI требует Workshop ресурсов
- libpq загружается динамически
