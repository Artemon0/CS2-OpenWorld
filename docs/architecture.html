Architecture

Gameplay rules stay on the server; engine integration, gameplay modules and persistence are separated.

Runtime layers

The Metamod plugin entry initializes OW Core. ModuleManager starts configured modules; the event bus carries typed lifecycle events, while the service registry exposes versioned interfaces. Adapters isolate engine and database details from gameplay code.

  • src/core/ — plugin lifecycle, module manager, event bus, service registry, cluster config.
  • src/modules/ — core, character, transfer, inventory and economy.
  • src/adapters/ — CS2 redirection, PostgreSQL and text output.
  • src/ui/ — UI routing, text HUD, input and experimental particle menus.

Server authority & sessions

Steam identity is trusted only after engine authorization. Client input is a request; the server validates ownership and state. Async database results are applied on the game thread only if the originating player session is still current.

Persistence & cluster routing

PostgreSQL is the source of truth. A bounded local cache is used only for player settings. Cluster routing assigns authenticated players and saves route changes before redirecting. Redirect means reconnect; live state and position do not migrate.

Boundaries

The server-only UI adapter sends text and notifications; it cannot open arbitrary Panorama panels. Particle UI is experimental and off by default. Read feature status, setup, or the source architecture overview.
