Complete Architecture Specification

The original Russian design document translated and structured. Covers every architectural decision, module responsibility, persistence model, cluster routing, and known implementation boundaries.

Design Principles

  • Server authority: The server owns gameplay state. Client input is a request, not proof that a player owns an item, balance, or completed action.
  • Modularity: Gameplay features are separate modules connected through explicit services and events.
  • Persistence boundaries: Modules use persistence interfaces rather than issuing SQL directly.
  • Safe engine lifetimes: Long-lived state should use stable identifiers and validated handles instead of retaining raw engine pointers.
  • UI independence: Gameplay logic should not depend on a particular rendering mechanism.

The core owns plugin lifecycle and wires adapters and modules together. Modules publish and consume typed events and versioned service interfaces. The persistence adapter centralizes parameterized database operations.

OW Core (src/core/)

Plugin Entry & Lifecycle

src/core/plugin.cpp implements the Metamod lifecycle, player lifecycle hooks, the ow_status command, Steam authorization checks, game event hooks, and module initialization.

Module Manager

src/core/module_manager.* handles module registration, startup ordering, and shutdown. Modules declare dependencies; the manager resolves and starts them in order.

Event Bus

src/core/event_bus.h carries typed lifecycle events. Publish is synchronous on the game thread; Enqueue/DispatchPendingEvents (drained once per OnGameFrame) deliver owned copies for self-publishing listeners. Re-entrant cycles are rejected past MaxPublishDepth. Cross-thread publishing is unsupported.

Service Registry

src/core/service_registry.h exposes versioned interfaces. Modules register services; consumers request by interface ID and version. This decouples modules from concrete implementations.

Configuration

src/core/cluster_config.* loads and validates the server/zone topology from openworld.ini. Config is read once at load; hot-reload is planned (core/config_manager in roadmap).

Gameplay Modules (src/modules/)

Character Module

Manages character listing, creation, and selection. src/modules/character/ and src/modules/persistence/player_character_worker.* perform async character loads off the game thread. Commands: !character list, !character create , !character select . A sole character is selected automatically.

Transfer Module

Implements route assignment and reconnect-based server transitions. src/modules/transfer/ contains the validation state machine, idempotency checks, state transitions, and expiry. Does not preserve runtime player state across servers. Exposes ITransferService v1 while running. Cross-server coordinator (reservation, tokens, ownership fencing, destination arrival handshake) is open (ADR-025).

Inventory Module

src/modules/inventory/ exposes IInventoryService for inventory snapshots. Loads/stores JSON snapshots with versioned compare-and-swap (stale revision rejected). Item acquisition, mutation commands, and gameplay rules are not implemented.

Economy Module

src/modules/economy/ exposes IEconomyService for wallet operations and idempotent transactions. !balance shows the selected character's wallet. Gameplay economy loops are not implemented.

Persistence Module

src/modules/persistence/ retains optional generic LRU, async-warmup, and RESP2 Redis fallback sources. CMake excludes these unless OW_ENABLE_CACHE_FALLBACK=ON. player_route_worker.* performs async route lookups and assignments. The standard build includes only a small process-local cache for LoadPlayerSettings (512 entries, 4 MiB, 30s TTL).

Adapters (src/adapters/)

PostgreSQL Adapter

src/adapters/persistence/postgres_adapter.* dynamically loads libpq at runtime, checks connection on plugin load, and provides parameterized database operations. Owner-checked character loads, revision-checked inventory saves, idempotent economy transactions. Settings load asynchronously after full Steam authentication; results applied on game thread only if player session is still current.

Panorama Text Adapter

src/adapters/panorama/ sends per-player notifications, console, chat, and center text through CS2 TextMsg. Text HUD toggled with !hud [on|off|toggle]. Cannot open arbitrary Panorama panels, run JS, or expose client actions. Map display falls back to current server map name.

Input Adapter

src/ui/input/ provides per-player input contexts, edge-triggered snapshot handling, and logical action dispatch. Optional client config forwards E→inventory and TAB→map action while preserving stock +use and scoreboard. Does not replace scoreboard or expose arbitrary keyboard events to server.

Particle Menu (Experimental)

src/ui/particle/ provides C++ menu model and sessions. Requires adapters.particle_menu = true (opt-in), Workshop resources, and live-game validation. Installs a KHook transmit filter; defaults off.

Server Clusters & Routing

Cluster Configuration

Each server has a unique core.server_id, shared environment, full [servers.*] list, and optional [zones.*] rectangular XY areas. All servers must use the same PostgreSQL database and routing migration (004).

Server Affinity

PostgreSQL stores player-to-server affinity. After Steam auth, the server async looks up the assigned server. First-time players → [routing].lobby_server_id. !go atomically updates assignment in PostgreSQL, then sends CS2 connect. This is a reconnect, not seamless transfer — position, inventory mutations, and runtime state do not carry over.

Zone Transitions

Automatic transitions use [zones.*] rectangles. When a living, authenticated player crosses into another server's zone, destination is saved to PostgreSQL and client reconnects. Checks run ~4×/sec on game thread. Requires routing.enforce_server_affinity = true, modules.transfer = true, and a configured zone for the current map. All zones must share one world coordinate system. Destination map chooses spawn point; position/velocity do not carry over.

Failure Modes

  • Unknown/unavailable destination → fail closed (error logged, no redirect)
  • PostgreSQL disabled or migration missing → routing fails closed
  • Overlapping zones assigned to different servers → no transition
  • Player outside all zones → no transition

Persistence & Threading Model

Source of Truth

PostgreSQL is the authoritative store for persistent player and world data. Schema in database/migrations/ (001–004), owned by ow_migrator role, accessed by ow_app with restricted permissions.

Settings Cache

Bounded process-local cache only for LoadPlayerSettings: 512 entries max, 4 MiB total JSON payload, 30s TTL. Successful writes refresh cache; failed writes invalidate entry. Changes on another server may take up to 30s to become visible. Not used for: characters, inventory, balances, transactions, authentication, transfer state.

Threading

Database work that may block runs off the game thread (background workers). Results affecting engine state are applied on the game thread after validating the player session (SteamID + slot still match). The Redis/LRU/warmup fallback sources are experimental, excluded from default build, not connected to player lifecycle.

UI System (src/ui/)

UI Manager

src/ui/ui_manager.* provides per-player UI routing and profile-based HUD text elements. Current renderer uses transient center-screen TextMsg messages, not custom graphical panels.

Text HUD

Multi-line center-screen text showing server, Steam session, and settings-load status. Toggled via !hud. Not a graphical Panorama panel.

Input Handling

Per-player input contexts with edge-triggered snapshots. Logical actions dispatched to modules. Client-side bind file (optional) maps E→inventory, TAB→map while preserving stock behavior.

Particle UI (Experimental)

C++ menu model with particle-based rendering. Requires Workshop resources, adapters.particle_menu = true, KHook transmit filter. Disabled by default.

Known Implementation Boundaries

Not Implemented

  • Seamless transfers (no disconnect/reconnect)
  • Transfer snapshots & state restoration
  • Position restoration across servers
  • Automatic portal/trigger detection
  • NPCs, quests, dialogue trees
  • Vehicles, vehicle economy
  • Complete gameplay inventory (pickup, crafting, mutation)
  • Health/bleeding/medical systems
  • Weapon economy extensions
  • Social features (parties, friends, chat channels)
  • Audio/music zones
  • Graphical map panels (Panorama)
  • Admin commands, bans, audit trail
  • Role/permission model
  • Sector/streaming management
  • Cross-server coordinator RPC
  • Message transport between cluster nodes
  • Config hot-reload
  • Structured diagnostics dump

Known Gaps in Current Code

  • plugin.cpp is a single large TU; chat router, route coordinator, character/settings coordinators, hook binder are natural extraction points
  • Gamedata Offsets block lacks Touch, StartTouch, EndTouch, CollisionRulesChanged; helpers unused, degrade to no-op
  • Character, inventory, wallet never cached — every read hits PostgreSQL (correct but may need read-through cache at scale)
  • Event delivery single-threaded; synchronous Publish; listener unbinding during publish skips remaining listeners intentionally
  • TransferManager purely in-process, no locks; game-thread only; not a cross-server coordinator

Database Schema Overview

All tables in ow schema. Migrations applied in order:

  • 001_core.sql — core tables, player settings, characters
  • 002_application_functions.sql — helper functions for character/settings ops
  • 003_inventory_functions.sql — inventory snapshot with revision CAS, economy/wallet
  • 004_player_server_routes.sql — server affinity & routing (required for cluster)

Bootstrap scripts create ow_migrator (schema owner) and ow_app (restricted) roles. 003_app_permissions.sql grants application permissions. Never run plugin as postgres or ow_migrator.

Build & Deploy

Requirements

  • CMake 3.19+
  • 64-bit MSVC (Windows) or Clang (Linux)
  • hl2sdk-cs2 and metamod-source submodules initialized
  • PostgreSQL 14+ and libpq runtime

Build Commands

# Linux
git submodule update --init --recursive
export CC=clang CXX=clang++
cmake -S . -B build-linux -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build-linux -j
ctest --test-dir build-linux --output-on-failure

# Windows
cmake -S . -B build -A x64
cmake --build build --config Release

Important Flags

  • Exceptions disabled (-fno-exceptions / _HAS_EXCEPTIONS=0). Report failures via return values, bool, std::optional, or IsRunning()/IsEnabled() accessors.
  • -DOW_ENABLE_CACHE_FALLBACK=ON includes experimental Redis/LRU/warmup sources (excluded by default).
  • Gamedata (gamedata/cs2-openworld.games.txt) drives every offset/signature. Verify before shipping: python tools/update_offsets.py --check.

Package Output

Build writes to build-windows-release/package (or build-linux/package). Contains addons/ and cfg/ mirroring server game/csgo/. Copy both folders into server game/csgo/. Provide libpq at runtime. See PACKAGE_INSTALL.txt for details.
