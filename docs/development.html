Development guide

A map of the source tree and constraints that keep new features compatible with the CS2 server runtime.

Repository map

  • src/core/ — Metamod entry point, module lifecycle, services and events.
  • src/modules/ — gameplay and persistence coordination.
  • src/adapters/ — engine, database and UI transport integration.
  • src/ui/ — UI state, HUD, input and particle menu.
  • database/migrations/ — ordered PostgreSQL schema changes.
  • gamedata/ — engine offsets and signatures.
  • tests/ — unit, integration and performance test sources.

Implementation rules

  • C++20; 64-bit MSVC on Windows or Clang on Linux.
  • Exceptions are disabled in plugin and test targets. Report failures via return values, flags or optional results.
  • Parameterize database operations and run them off the game thread; validate session before applying async results.
  • Add schema changes as numbered migrations; PostgreSQL remains the source of truth.
  • Use stable IDs and validated handles for state that outlives engine callbacks.

Build & verify

Follow build instructions. Before release, verify gamedata against target server binaries with tools/update_offsets.py. See unit tests and integration tests.
